# 01 产品范围与功能规格

本页定义第一版（v1.0）要交付的功能与验收标准，是研发、测试与产品验收的共同依据。

## 版本目标与范围边界

**v1.0 的目标**：在 macOS、Windows、Linux 上交付一个原生 Agent 工作台，日常对话、工具调用、权限审批、计划执行与模型管理的体验不低于 MkAgent Electron 版，同时作为 AgentKit 框架的参考应用。

**范围内（v1.0）**

- 自动拉起并管理本地 mkagent 后端（sidecar），连接断开自动恢复。
- 工作区、会话管理、流式对话、工具卡片、后台任务、权限模式与审批、计划审阅。
- 模型连接：API Key 预设、自定义 OpenAI / Anthropic 兼容端点、Ollama、ChatGPT Plus OAuth、Claude Pro/Max OAuth。
- 输入：附件、@ 文件 / 文件夹、Skill 调用、草稿、模型与思考等级选择。
- 设置、首次启动引导、系统通知、原生菜单与快捷键、中英文、自动更新。
- 联网能力只有 `web_search` 与 `web_fetch`。

**范围外（v1.0 明确不做）**

| 能力 | 处理方式 |
| --- | --- |
| 交互式浏览器工具（Browser pane） | 不声明 `client:browser:invoke`；启动时关闭 `browserToolEnabled` |
| Coding 模式：Git worktree、PR 监视、自动合并 | 不调用 `git:*`、`prWatch:*`；不展示相关入口 |
| 消息批注（annotations）与追问编辑 | 已有批注只读展示，不提供新增 / 编辑 |
| RTK、Mini chat、Release notes 弹窗 | 不展示 |
| 连接远程 mkagent 服务器的界面 | 框架层保留 `Backend::Remote`，界面不提供入口 |
| JS 扩展（gpui-shell）、可自由拖拽的 Dock 布局 | 留给阶段 4 框架化 |
| WebUI、CLI | 继续使用上游自带版本 |

## 关键用户流程

以下流程是端到端测试的脚本基础，括号内为涉及的 RPC 频道。

### U1 首次启动

1. 应用启动 → 启动画面显示“正在启动后端” → sidecar 就绪 → 握手成功。
2. 客户端调用 `tools:setBrowserToolEnabled(false)`（仅首次，记录在本地偏好）。
3. 调用 `LLM_Connection:listWithStatus`；无已认证连接 → 进入引导。
4. 用户选择连接方式：API Key 预设（供应商列表取自 `pi:getApiKeyProviders`）/ 自定义端点 / Ollama / ChatGPT / Claude。
5. 填写后点“测试”（`settings:testLlmConnectionSetup`）→ 成功后“保存”（`settings:setupLlmConnection`）→ 设为默认（`LLM_Connection:setDefault`）。
6. 进入主窗口，自动新建一个空会话并聚焦输入框。

### U2 一次带工具调用的对话

1. 用户输入并发送 → 立即显示乐观用户消息（`isPending`），会话进入 processing。
2. `sessions:sendMessage` 返回 `{accepted:true, messageId}`（消息已落盘）。
3. 收到 `user_message` → 用乐观消息 id 对应替换；收到 `text_delta` / `tool_start` / `tool_result` → 回合卡实时更新。
4. 收到 `complete` → 会话回到 idle，输入框可用；若窗口不在前台，发“回合完成”通知。

### U3 权限审批

1. 在“探索”或“询问”模式下，Agent 调用写文件或 bash → 收到 `permission_request`。
2. 会话状态变为等待审批：审批卡出现在回合卡底部，侧栏会话显示“待审批”标记。
3. 用户点“允许” / “拒绝” / “本会话始终允许” → `sessions:respondToPermission(sessionId, requestId, allowed, alwaysAllow)`。
4. 审批卡收起为一行记录，回合继续；拒绝则工具卡显示“已拒绝”。

### U4 计划审阅与执行

1. 收到 `plan_submitted` → 显示计划卡（Markdown 正文 + “接受”“接受并压缩”）。
2. “接受”：若当前为探索模式，先 `sessions:command{setPermissionMode:'allow-all'}`；再发送批准消息（文案键 `plan.approved`，输入框已有内容按 `plan.additionalUserContext` 格式附加）。
3. “接受并压缩”：`sessions:command{setPendingPlanExecution, planPath, draftInputSnapshot}` → 发送 `/compact` → 压缩完成（`info` 事件 `statusType:'compaction_complete'`）且会话空闲后，按 03 页“待执行计划调度器”发送批准消息。

### U5 带附件与提及的发送

1. 拖入 / 粘贴 / 选择文件 → 本地读取为 `FileAttachment`（图片生成缩略图）。
2. 发送时逐个 `file:storeAttachment(sessionId, attachment)` 得到 `StoredAttachment`；失败项插入一条 warning 消息。
3. 用 StoredAttachment 的 `storedPath`、`markdownPath`、`resizedBase64` 补充 FileAttachment，连同 `skillSlugs` 与 `badges` 调用 `sessions:sendMessage`。

### U6 后端崩溃恢复

1. sidecar 进程退出 → 状态栏显示“后端已断开，正在重启”。
2. 自动重启并重新握手（新 token）→ 全量刷新会话列表与当前会话。
3. 崩溃时正在运行的会话由后端标为 interrupted，界面显示“已中断，可继续”。

## 非功能需求

基准机型：MacBook Air M1 8 GB、Windows 11 i5-8250U 8 GB、Ubuntu 22.04 i5-8250U 8 GB。所有指标在 release 构建下测量。

| 类别 | 指标 | 目标 |
| --- | --- | --- |
| 启动 | 冷启动到输入框可用 | ≤ 1.5 秒（M1），≤ 3 秒（其余基准机） |
| 启动 | 主窗口首帧 | ≤ 300 ms，不等后端就绪 |
| 渲染 | 流式 50 token/s 时帧时间 | p95 ≤ 16 ms |
| 渲染 | 打开 1 万条消息的会话 | ≤ 800 ms；滚动 ≥ 60 fps |
| 渲染 | 单个工具结果 10 万行 | 折叠状态不卡顿；展开后虚拟化渲染 |
| 内存 | GPUI 进程空闲 / 打开 10 个会话 | ≤ 150 MB / ≤ 300 MB（不含 sidecar） |
| 事件 | 事件到达到界面更新 | ≤ 1 帧（同帧内合并） |
| 稳定性 | 崩溃率 | < 0.5% 会话；连续 7 天内部使用无阻断级问题 |
| 稳定性 | 后端崩溃恢复 | ≤ 5 秒；不丢已落盘消息 |
| 安全 | 密钥与 token | 只存于后端凭据存储；GPUI 进程不落盘、不写日志 |
| 安全 | RPC 绑定 | 只监听 127.0.0.1；每次启动随机 32 字节 token |
| 无障碍 | 可交互元素 | 全部有 AccessKit 角色与名称；全流程可仅用键盘完成 |
| 国际化 | 文案 | 中英文键集一致；界面无硬编码文案（CI 检查） |
| 安装包 | 体积 | macOS DMG ≤ 220 MB（大头为后端自带的 Bun、uv、文档工具资源），以阶段 0 实测校准 |

## 已拍板的决策

00 页列出的待决事项按下表默认执行；如需改变，在阶段 1 开始前提出。

| 事项 | 决策 | 理由 |
| --- | --- | --- |
| 产品与框架命名 | 代码内用占位名 `agentkit` / `Workbench`，品牌名、Bundle ID、数据目录名、URL scheme 全部集中在 `brand.toml` | 改名只改一个文件，不阻塞开发 |
| 数据目录 | 独立目录 `~/.agentkit`（通过 `CONFIG_DIR` 传给后端） | 后端对同一配置目录加单实例锁（`.server.lock`），与 Electron 版共用会导致两者无法同时运行；迁移通过会话导入完成（见 07 页） |
| 上游维护方式 | git submodule 锁定 tag + `backend/patches/` 最小补丁；补丁同时以 PR 形式提交上游 | 只有 3 个小补丁（见 07 页），不值得长期 fork |
| 首发平台 | macOS 先行，Windows / Linux 阶段 3 | 签名公证链路最长，先跑通；GPUI 在 macOS 最成熟 |
| 交互式浏览器 | v1 不做 | 见 00 页 |
| 异步运行时 | RPC 客户端使用 smol + `async-tungstenite`，运行在独立线程 | 与 GPUI / GPUI Kit 的 smol 生态一致，不引入 tokio |
| 布局 | v1 为固定布局（侧栏 + 主区 + 可收起右侧面板），不使用可拖拽 Dock | 降低复杂度；Dock 留给框架化阶段 |
| 遥测 | 崩溃上报默认关闭；不采集使用数据 | 本地优先定位 |
| JS 扩展 | v1 不开放 | 安全模型需要单独设计 |
