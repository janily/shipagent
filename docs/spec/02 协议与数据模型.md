# 02 协议与数据模型

本页是 `agentkit-protocol` 与 `agentkit-client` 的实现依据，所有字段名、频道名均取自 mkagent v0.2.6 源码。

## 帧格式与 Rust 类型定义

每个 WebSocket 文本帧是一个 JSON `MessageEnvelope`（上游 `packages/shared/src/protocol/types.ts`）。协议版本固定为 `"1.0"`。字段名保持 camelCase，由 serde 重命名。

```rust
// crates/agentkit-protocol/src/envelope.rs
#[derive(Serialize, Deserialize, Debug, Clone, Default)]
#[serde(rename_all = "camelCase")]
pub struct Envelope {
    pub id: String,                       // 请求用 UUIDv4；响应原样回传
    #[serde(rename = "type")]
    pub kind: EnvelopeKind,
    #[serde(skip_serializing_if = "Option::is_none")] pub channel: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub args: Option<Vec<serde_json::Value>>,
    #[serde(skip_serializing_if = "Option::is_none")] pub result: Option<serde_json::Value>,
    #[serde(skip_serializing_if = "Option::is_none")] pub error: Option<WireError>,
    // 握手
    #[serde(skip_serializing_if = "Option::is_none")] pub protocol_version: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub workspace_id: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub token: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub client_id: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub client_capabilities: Option<Vec<String>>,
    #[serde(skip_serializing_if = "Option::is_none")] pub registered_channels: Option<Vec<String>>,
    #[serde(skip_serializing_if = "Option::is_none")] pub server_version: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub max_message_bytes: Option<u64>,
    // 可靠投递
    #[serde(skip_serializing_if = "Option::is_none")] pub seq: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")] pub last_seq: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")] pub reconnect_client_id: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub reconnected: Option<bool>,
    #[serde(skip_serializing_if = "Option::is_none")] pub stale: Option<bool>,
    #[serde(skip_serializing_if = "Option::is_none")] pub server_id: Option<String>,
}

#[derive(Serialize, Deserialize, Debug, Clone, Copy, PartialEq, Eq, Default)]
#[serde(rename_all = "snake_case")]
pub enum EnvelopeKind { #[default] Request, Response, Event, Error, Handshake, HandshakeAck, SequenceAck }

#[derive(Serialize, Deserialize, Debug, Clone)]
pub struct WireError { pub code: ErrorCode, pub message: String, #[serde(default)] pub data: Option<serde_json::Value> }
```

**各类帧的必填字段**

| type | 方向 | 必填 | 说明 |
| --- | --- | --- | --- |
| `handshake` | C→S | `id`、`protocolVersion`、`token`、`workspaceId`、`clientCapabilities` | 重连时加 `reconnectClientId`、`lastSeq`；不发 `webContentsId` |
| `handshake_ack` | S→C | `clientId`、`registeredChannels`、`serverVersion`、`maxMessageBytes` | 重连时可能带 `reconnected`、`stale` |
| `request` | 双向 | `id`、`channel`、`args` | S→C 的 request 即客户端能力调用 |
| `response` | 双向 | `id`、`result` | `id` 与请求一致 |
| `error` | 双向 | `id`、`error` | 握手失败时服务端可能随后关闭连接 |
| `event` | S→C | `channel`、`args`、`seq` | 推送；`args` 为位置参数 |
| `sequence_ack` | C→S | `lastSeq` | 每 5 秒一次 |

**二进制值**：任意位置的 `Uint8Array` 以 `{"__craftRpcType":"u8","base64":"…"}` 传输。客户端在解码 `args` / `result` 前递归把该对象转为 `Bytes`；发送二进制时反向编码。v1 只在附件与缩略图读取中遇到。

## 连接生命周期与可靠投递

客户端行为以上游 `packages/server-core/src/transport/client.ts`（`WsRpcClient`）为准，并用上游 `apps/electron/src/__tests__/transport.test.ts` 的场景做对照测试。

&#91;embedded content: 连接状态机 · 7 个状态\]

**规则**

1. **握手**：连接建立后 5 秒内必须发 `handshake`，否则服务端以 4003 关闭。收到 `handshake_ack` 前不发任何其他帧；期间业务调用排队。
2. **工作区绑定**：握手的 `workspaceId` 决定 `sessions:get` 与推送范围。切换工作区调用 `window:switchWorkspace`，并把新 id 记入客户端，以便重连握手使用。每个窗口一条连接。
3. **序号**：记录最大 `seq` 为 `lastSeenSeq`；发现跳号只记 warn 日志（与上游一致，不重排）。每 5 秒发送 `sequence_ack{lastSeq}`。
4. **心跳**：服务端每 30 秒 ping；客户端 WebSocket 库必须自动回 pong。连续 2 次未响应服务端会断开。
5. **重连退避**：延迟 = min(1000 ms × 2^尝试次数, 30000 ms)；连接稳定 10 秒后计数归零。重连握手带 `reconnectClientId`（上一个 clientId）与 `lastSeq`。
6. **是否全量刷新**：ack 未带 `reconnected:true`（服务端不认得旧客户端）或带 `stale:true` → 全量刷新。服务端保留每客户端最多 500 条 / 30 秒的事件，断开的客户端缓冲保留 60 秒。
7. **挂起请求**：断线时所有未完成请求立即以 `CLIENT_DISCONNECTED` 结束；不自动重发写操作。
8. **sidecar 重启**：生成新 token、新端口，按首次连接处理（必定全量刷新）。
9. **对外状态**：`ConnectionState { Spawning, Connecting, Handshaking, Connected, Reconnecting{attempt, next_retry_ms}, Restarting{attempt}, Fatal{reason} }`，供状态栏显示。

## SessionEvent 处理表

`session:event` 的载荷是 `SessionEvent`（上游 `packages/shared/src/protocol/dto.ts`），以 `type` 区分。Rust 端定义为 `#[serde(tag = "type", rename_all = "snake_case")]` 枚举，并保留 `#[serde(other)] Unknown`；未知事件只记录 debug 日志。

归约语义以上游渲染进程事件处理器为准（`apps/electron/src/renderer/event-processor/`：`processor.ts`、`handlers/text.ts`、`handlers/tool.ts`、`handlers/session.ts`，连同 helpers.ts 共约 1,600 行），逐函数移植，上游单测同步移植为 Rust 单测。下表为要点，与上游不一致时以上游代码为准。

| 事件 | 关键字段 | 对状态的作用 | 界面 / 副作用 |

## 核心数据类型

类型由 `tools/codegen` 从上游 TS 生成（见 05 页），以下为生成结果应满足的形状，作为评审依据。所有结构体加 `#[serde(rename_all = "camelCase")]`；可选字段为 `Option<T>` 且 `#[serde(default)]`；未知字段忽略（不加 `deny_unknown_fields`），以兼容上游新增字段。

    pub supports_branching: Option<bool>, pub parent_session_id: Option<String>,

## 客户端能力（client:\*）

服务端会对声明了能力的客户端发 `request` 帧，客户端必须在超时前回 `response` 或 `error`。GPUI 客户端握手时声明下表前 5 项，**不声明** `client:browser:invoke`。

| 能力 | 参数 | 必须返回 | 实现 | 谁会触发 |
| --- | --- | --- | --- | --- |
| `client:openExternal` | `url` | `null` | GPUI `cx.open_url(url)`；只允许 http / https / mailto | Agent 或服务端要求打开链接 |
| `client:openPath` | `path` | `{error?}` | `opener::open(path)` | 打开文件 |
| `client:showItemInFolder` | `path` | `null` | `opener::reveal(path)` | 在文件管理器中显示 |
| `client:confirmDialog` | `{type?, title, message, detail?, buttons[], defaultId?, cancelId?}` | `{response: 按钮序号}` | GPUI Kit `AlertDialog`（窗口内模态）；无窗口时用 `rfd::MessageDialog` | 删除会话确认（`auth:showDeleteSessionConfirmation`）等 |
| `client:openFileDialog` | `{title?, defaultPath?, properties?[], filters?[]}` | `{canceled, filePaths[]}` | GPUI `cx.prompt_for_paths(PathPromptOptions{files, directories, multiple})`；`properties` 含 `openDirectory` → 选目录 | `dialog:openFolder`、工作目录选择 |
| `client:browser:invoke` | — | — | v1 不声明 | — |

实现要求：能力处理在 GPUI 前台线程执行（需要窗口与对话框），客户端线程把请求转发到前台并等待结果；对话框以最近聚焦的窗口为父窗口。未注册的能力回 `error{code:'CAPABILITY_UNAVAILABLE'}`。

## 错误码与处理策略

传输层错误码来自上游 `ErrorCode`；业务错误通常是 `HANDLER_ERROR` + 可读 `message`。客户端一律按 `code` 分支，不解析 message 文本。

| 错误码 | 含义 | 客户端处理 |
| --- | --- | --- |
| `AUTH_FAILED` | token 错误 | sidecar 模式：重启 sidecar 并生成新 token；远程模式：提示重新输入 |
| `PROTOCOL_VERSION_UNSUPPORTED` | 协议不兼容 | 阻断页：“后端版本不匹配，请重新安装” |
| `CHANNEL_NOT_FOUND` | 频道未注册 | 调用前已查 `registeredChannels`，出现即 bug；记日志并隐藏入口 |
| `SESSION_NOT_IDLE` | 会话忙 | 提示“会话正在运行”，不重试 |
| `SESSION_ID_CONFLICT` | 导入 id 冲突 | 导入改用 `fork` 模式重试一次 |
| `REQUEST_TIMEOUT` / `CLIENT_REQUEST_TIMEOUT` | 超时 | 只读类请求自动重试 1 次；写类请求不重试，提示用户 |
| `CLIENT_DISCONNECTED` | 连接断开 | 交给重连状态机；挂起的请求以该错误结束 |
| `TRANSFER_TOO_LARGE` | 单帧超过 `maxMessageBytes` | 附件过大：提示并从本次发送中移除 |
| `CAPABILITY_UNAVAILABLE` / `BROWSER_*` | 能力不可用 | 工具卡显示“当前版本不支持” |
| `HANDLER_ERROR` | 业务错误 | 展示 `message`（Toast 或表单内联错误） |

会话内的模型 / 工具错误不走传输错误，而是 `error` / `typed_error` 事件。`typed_error.error.actions` 中的 `retry` 重新发送上一条用户消息；`settings` 打开对应设置页（模型连接）；`open_url` 走 `cx.open_url`。
