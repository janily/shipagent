# 05 工程规范与质量

本页规定开发环境、代码与提交规范、CI 门禁、测试与发布流程。

## 工具链、仓库初始化与本地开发

**开发机前置条件**

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Rust | 由 `rust-toolchain.toml` 锁定（阶段 0 确定） | 客户端 |
| Bun | ≥ 1.3.14（与上游要求一致） | 构建后端 |
| Node.js | ≥ 18 | 上游构建脚本依赖 |
| Python 3.12 + uv | 与上游一致 | 后端文档工具资源 |
| Xcode Command Line Tools | 最新 | macOS 编译、签名 |
| Visual Studio Build Tools（MSVC） | 2022 | Windows 编译 |
| Linux 系统库 | 按 GPUI Kit 入门文档安装（xkbcommon、Wayland / X11、Vulkan 等） | Linux 编译 |

**常用命令**（均由 `xtask` 提供，阶段 0 实现）

```bash
git clone --recurse-submodules <repo>
cargo xtask backend build        # bun install → 应用 backend/patches → build-server → 输出到 target/backend/<平台>
cargo xtask codegen              # 从上游 TS 生成 agentkit-protocol 类型与频道常量
cargo xtask i18n                 # 转换上游文案并检查键集
cargo run -p workbench           # 开发运行，自动使用 target/backend
cargo xtask fixtures record <场景>   # 录制事件夹具（见下文）
cargo xtask package --target macos-arm64   # 打包（含签名需配置证书环境变量）
```

**开发期环境变量**

| 变量 | 作用 |
| --- | --- |
| `AGENTKIT_BACKEND_DIR` | 指定后端产物目录（默认 `target/backend/<平台>`） |
| `AGENTKIT_CONFIG_DIR` | 隔离数据目录，传给后端 `CONFIG_DIR`；多人调试或跑测试时必须设置 |
| `AGENTKIT_REMOTE_URL` + `AGENTKIT_REMOTE_TOKEN` | 不启动 sidecar，连接手动启动的后端（便于在后端源码上调试） |
| `AGENTKIT_LOG` | 日志级别，如 `agentkit_client=debug,info` |
| `AGENTKIT_RECORD_EVENTS` | 把收到的 `session:event` 写入指定 JSONL 文件 |

从后端源码启动的方式：在 `backend/mkagent` 目录执行 `CONFIG_DIR=/tmp/ak-dev MKAGENT_SERVER_TOKEN=dev bun run packages/server/src/index.ts`，再以 `AGENTKIT_REMOTE_URL=ws://127.0.0.1:9100 AGENTKIT_REMOTE_TOKEN=dev cargo run -p workbench` 连接。

## 代码规范

1. `cargo fmt` 默认配置；`cargo clippy --all-targets -- -D warnings` 必须通过。
2. 非测试代码禁止 `unwrap()` / `expect()`，确定不可能失败处允许 `expect("说明原因")`。
3. 库 crate 用 `thiserror` 定义错误枚举；`agentkit-app` 与 `apps/*` 可用 `anyhow`。错误必须在界面层转为可读文案，不得直接把 Debug 输出显示给用户。
4. GPUI 前台线程禁止阻塞：不得调用同步 IO、`block_on`、文件读写（用 `cx.background_executor()`）。
5. 分层：`agentkit-ui` 不得依赖 `agentkit-client`；只有 `agentkit-app` 中的控制器调用 RPC；RPC 只通过 `agentkit_client::api` 门面。
6. 界面文案只用 `t!()`；不得硬编码用户可见字符串（CI 检查）。
7. 每个可交互元素设置 `id`、`role`、`aria_label`（参照 GPUI Kit Coding Guides 与 `crates/kit/tests/ui.rs` 示例）。
8. 颜色、字号、间距只用主题 Token 与 GPUI Kit 尺寸方法，不写死色值。
9. `unsafe` 只允许出现在 `agentkit-capabilities` 的平台模块，并附 `// SAFETY:` 说明。
10. 公开 API 必须有文档注释；`#![deny(missing_docs)]` 对 `agentkit-client`、`agentkit-store::core`、`agentkit-app` 的公开模块开启。
11. 从上游移植的函数在文档注释中注明来源文件与上游 tag，例如 `/// Ported from mkagent v0.2.6 apps/electron/src/renderer/event-processor/handlers/text.ts`。
12. 日志中禁止出现敏感内容（见 03·日志规范）。

## 分支、提交与评审

- **分支**：主干开发，`main` 始终可发布；功能分支命名 `<类型>/<任务编号>-<简述>`，如 `feat/T-1-07-reducer`；分支存活不超过 3 个工作日。
- **提交**：Conventional Commits（`feat`、`fix`、`refactor`、`test`、`docs`、`chore`），正文引用任务编号与功能编号，如 `feat(store): port text_delta reducer (T-1-07, F-15)`。
- **PR**：建议单个 PR 变更 ≤ 400 行（生成代码与夹具除外）；描述包含“做了什么 / 如何验证 / 未验证什么”三段；界面变更附截图或录屏。
- **评审**：默认 1 人批准；`agentkit-protocol`、`agentkit-client`、`agentkit-sidecar`、`backend/patches/` 需 2 人批准（含技术负责人）。由 `CODEOWNERS` 强制。
- **合并**：Squash merge；CI 全绿才可合并。

## CI 流水线与门禁

CI 使用 GitHub Actions。“必过”表示 PR 合并门禁。

| 作业 | 触发 | 平台 | 内容 | 门禁 |
| --- | --- | --- | --- | --- |
| `lint` | 每个 PR | Linux | `cargo fmt --check`、`clippy -D warnings`、`cargo deny check`（许可证 + 漏洞） | 必过 |
| `codegen-drift` | 每个 PR | Linux | 重新运行 `xtask codegen`，工作区有 diff 即失败 | 必过 |
| `i18n` | 每个 PR | Linux | 中英键集一致、代码中无硬编码文案、无未使用键 | 必过 |
| `unit` | 每个 PR | macOS arm64 + Linux（阶段 3 起加 Windows） | 全部单测；core 行覆盖率 ≥ 90%、client ≥ 80%（`cargo llvm-cov`） | 必过 |
| `ui` | 每个 PR | macOS arm64 | `gpui_kit::test` 界面测试 | 必过 |
| `contract` | 每个 PR（缓存后端产物） | macOS arm64 | 构建或复用后端 → 启动真实 sidecar + fake-llm → 跑客户端契约测试与 01 页 U1–U6 脚本 | 必过 |
| `perf` | 每晚 | macOS arm64 实体机 | 01 页非功能指标基准；与前一晚对比，退化 > 10% 告警 | 告警 |
| `package` | 每晚 + 打 tag | 全平台 | 打包、签名、公证；产物上传为 nightly 或 release | tag 时必过 |
| `upstream-canary` | 每周 | macOS arm64 | 用上游 `main` 最新提交跑 codegen + contract，提前发现协议变化 | 告警 |

## 测试规范与事件夹具录制

**fake-llm**：`tools/fake-llm` 是一个本地 OpenAI 兼容（`/v1/chat/completions`，SSE 流式）服务，按脚本返回文本与工具调用。脚本为 YAML，例如：

```yaml
# tools/fake-llm/scenarios/tool-then-answer.yaml
turns:
  - tool_calls:
      - name: read
        arguments: { path: README.md }
  - text: "这是一个示例项目。"
    chunk_ms: 20
```

测试中用自定义端点连接（`pi_compat` + `openai-completions` + `baseUrl` 指向 fake-llm）接入后端，不依赖任何真实模型与网络。

**事件夹具**：`cargo xtask fixtures record <场景>` 启动 sidecar + fake-llm，按场景脚本发送消息，把 `session:event` 流写入 `crates/agentkit-store/tests/fixtures/<场景>.jsonl`，并把结束时 `sessions:getMessages` 的结果写入 `<场景>.final.json`。回放测试断言：用夹具事件归约得到的消息列表，与 `final.json` 在去掉时间戳与临时 id 后一致。

**必备场景**（阶段 1 结束前全部录制）：纯文本、单工具、多工具并行、嵌套子 Agent、工具失败、权限允许、权限拒绝、取消、回合中追加消息、重试、typed\_error、计划提交、上下文压缩、后台 shell。

**测试层级与归属**

| 层 | 位置 | 要求 |
| --- | --- | --- |
| 单测 | 各 crate `src/**` 内 `#[cfg(test)]` | 上游移植逻辑必须同步移植上游单测 |
| 夹具回放 | `crates/agentkit-store/tests/` | 上述必备场景全部通过 |
| 客户端契约 | `crates/agentkit-client/tests/contract.rs` | 真实 sidecar；覆盖握手、请求、事件、重连、stale、能力回调、二进制、超时 |
| 界面 | `crates/agentkit-ui/tests/`、`crates/agentkit-app/tests/` | `#[gpui_kit::test]` + `TestWindowExt` 驱动输入，断言状态、焦点与无障碍角色 |
| 端到端 | `tests/e2e/` | 01 页 U1–U6，启动完整应用 + fake-llm |
| 手工 | 测试用例库 | 每个阶段末按 01 页功能清单逐项验收；中文输入法、无障碍（VoiceOver / NVDA）必须手工验证 |

## 打包、签名与发布

**版本号**：语义化版本，源头为根 `Cargo.toml` 的 `workspace.package.version`；通过 `MKAGENT_VERSION` 传给后端。预发布用 `-beta.N`。

| 平台 | 打包 | 签名 / 公证 | 应用内后端位置 |
| --- | --- | --- | --- |
| macOS arm64 / x64 | `.app` + DMG | 所有 Mach-O（主程序、`bun`、`rg`、`uv` 及 resources 中的可执行文件）逐一 `codesign --options runtime`；`bun` 需要 JIT 权限（`com.apple.security.cs.allow-jit`、`allow-unsigned-executable-memory`），具体权限集在阶段 0 验证；`notarytool` 公证并 staple | `Contents/Resources/backend/` |
| Windows x64 | Velopack Setup | `signtool` 签名所有 `.exe` 与 `.dll`（含 `bun.exe`、`rg.exe`、`uv.exe`）；建议 EV 证书以减少 SmartScreen 拦截 | `<安装目录>\backend\` |
| Linux x64 | AppImage + `.deb` | 可选 GPG 签名 | `usr/lib/<app>/backend/` |

**发布流程**

1. 从 `main` 打 tag `vX.Y.Z` → `package` 作业构建全平台产物。
2. 产物、校验和、Velopack 更新清单上传至 GitHub Releases（或自有 CDN）；客户端不内嵌任何发布凭据。
3. 先推 beta 渠道 48 小时，无阻断问题后推 stable。
4. 发布说明列出：功能编号变化、上游 mkagent tag、GPUI Kit 版本、已知问题。

签名证书与公证凭据只存放于 CI Secrets，打包脚本通过环境变量读取（`APPLE_SIGNING_IDENTITY`、`APPLE_NOTARY_*`、`WINDOWS_CERT_*`）。

## 安全与隐私

- RPC 只绑定 `127.0.0.1`；token 每次启动随机生成、只存内存、不写日志；不使用 WebUI。
- 密钥与 OAuth token 只在后端凭据存储中（上游为 AES-256-GCM 加密文件）；GPUI 进程不读取、不缓存。
- `client:openExternal` 只允许 `http`、`https`、`mailto`；`client:openPath` 拒绝可执行文件（`.app`、`.exe`、`.sh`、`.command`、`.bat` 等），改为“在文件管理器中显示”。
- Markdown 中的链接点击前显示完整 URL（Tooltip）；不自动加载远程图片（按上游行为，或显示占位点击加载）。
- 默认不采集任何使用数据；崩溃上报需用户主动开启，上报前去除路径中的用户名与消息内容。
- 依赖审计：`cargo deny`（含 RustSec 公告）每个 PR 运行；后端依赖沿用上游审计，升级上游时复查。
- 权限模式以后端策略为准：客户端不得在没有用户操作的情况下切到 `allow-all`（唯一例外：用户点击“接受计划”，与上游一致）。

## 完成定义（DoD）

一个任务只有同时满足以下条件才算完成：

- [ ] 对应功能编号的验收标准（01 页）全部达成，并在 PR 描述中逐条说明验证方式
- [ ] CI 必过作业全绿；新增逻辑有单测，行为变化有夹具或界面测试
- [ ] 新增文案已加入中英文资源
- [ ] 新增可交互元素有无障碍角色与名称，可仅用键盘操作
- [ ] 亮色与暗色主题下截图已附在 PR 中（界面类任务）
- [ ] 未引入新的全局状态、未在前台线程阻塞、未在日志中写入敏感内容
- [ ] 公开 API 有文档注释；与本文档不一致之处已同步修改文档
- [ ] 代码评审已通过（按 CODEOWNERS 人数）
