## agentkit-sidecar

职责：启动、就绪检测、监控、重启与退出 mkagent 后端。不依赖 GPUI，可在集成测试中单独使用。产物布局与环境变量见 07 页。

```rust
pub struct SidecarConfig {
    pub backend_dir: PathBuf,          // 含 server.js、vendor/bun、resources/
    pub config_dir: PathBuf,           // 传给 CONFIG_DIR，默认 ~/.agentkit
    pub log_dir: PathBuf,
    pub app_version: String,           // 传给 MKAGENT_VERSION
    pub extra_env: Vec<(String, String)>,  // 代理等
    pub ready_timeout: Duration,       // 默认 15s
    pub max_restarts: u32,             // 默认 3（滑动窗口 60s）
}

pub struct SidecarHandle { /* 私有 */ }
impl SidecarHandle {
    pub async fn start(cfg: SidecarConfig) -> Result<Self, SidecarError>;  // 返回即已就绪
    pub fn endpoint(&self) -> Endpoint;              // { url: "ws://127.0.0.1:<port>", token: Secret }
    pub fn events(&self) -> async_channel::Receiver<SidecarEvent>;
    pub async fn restart(&self) -> Result<Endpoint, SidecarError>;   // 代理变更等主动重启
    pub async fn shutdown(self, grace: Duration);    // 默认 5s
}

pub enum SidecarEvent {
    Exited { code: Option<i32>, stderr_tail: String },
    Restarted { endpoint: Endpoint },
    Fatal { reason: SidecarError },                 // 超过重启次数或启动失败
}

pub enum SidecarError { MissingRuntime(PathBuf), SpawnFailed(io::Error), ReadyTimeout,
    AlreadyRunning { pid: u32 },   // stderr 含 "Another server instance is already running"
    ExitedEarly { code: Option<i32>, stderr_tail: String } }
```

**启动流程**

1. 校验 `backend_dir/vendor/bun/bun`（Windows `bun.exe`）与 `server.js` 存在。
2. 生成 32 字节随机 token（hex）。
3. 以 `bun server.js` 启动，工作目录 `backend_dir`；环境变量见 07 页，其中 `MKAGENT_RPC_HOST=127.0.0.1`、`MKAGENT_RPC_PORT=0`（由系统分配端口），**不设** `MKAGENT_WEBUI_DIR`。
4. 逐行读取 stdout：遇到 `MKAGENT_SERVER_URL=ws://…` 即就绪，解析出实际端口。遇到 `MKAGENT_SERVER_TOKEN=` 开头的行**不得写入日志**；其余行写入 `sidecar.log`。stderr 同样写入日志，并保留最后 64 KB 供报错。
5. 超时未就绪 → 结束进程，返回 `ReadyTimeout`。

**进程树管理**：后端会再拉起 Pi 子进程及工具子进程。Unix 用 `setsid` 单独进程组，退出时对整组发 SIGTERM，宽限期后 SIGKILL；Windows 将子进程加入带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 的 Job Object，主程序崩溃时一并结束。后端已处理 SIGINT / SIGTERM 并释放 `.server.lock`；Windows 强制结束后遗留的锁由后端下次启动时自动判定为过期。

**重启策略**：进程意外退出 → 发 `Exited` → 1 秒后重启；60 秒内第 4 次退出发 `Fatal`。`AlreadyRunning` 不重试，直接 `Fatal`（提示另一个实例占用数据目录）。

**退出顺序**（由 agentkit-app 调用）：有运行中会话时先弹确认 → 对运行中会话调用 `sessions:cancel(id, true)` → 断开 RPC → `shutdown(5s)`。

## agentkit-client

职责：实现 02 页协议；对上提供无 GPUI 依赖的异步 API。

**线程模型**：`connect()` 启动一个名为 `agentkit-rpc` 的线程，内部 `smol::block_on` 运行连接主循环。对外句柄 `RpcClient` 可 `Clone`，所有方法经 `async_channel` 把命令发给主循环，结果由 oneshot 返回。GPUI 侧用 `cx.background_executor()` 或 `cx.spawn` 等待这些 future，不阻塞前台线程。

```rust
pub struct ClientOptions {
    pub endpoint: Endpoint,                  // url + token
    pub workspace_id: String,
    pub capabilities: Vec<String>,           // 见 02·客户端能力
    pub request_timeout: Duration,           // 默认 30s
    pub max_reconnect_delay: Duration,       // 默认 30s
    pub tls_ca: Option<PathBuf>,             // 仅远程 wss
}

#[derive(Clone)]
pub struct RpcClient { /* 私有 */ }
impl RpcClient {
    pub fn connect(opts: ClientOptions) -> Self;                     // 立即返回，后台连接
    pub async fn invoke<T: DeserializeOwned>(&self, channel: &str, args: Vec<Value>) -> Result<T, RpcError>;
    pub async fn invoke_timeout<T: DeserializeOwned>(&self, channel: &str, args: Vec<Value>, t: Duration) -> Result<T, RpcError>;
    pub fn subscribe(&self, channel: &str) -> async_channel::Receiver<Vec<Value>>;   // 无界队列，不丢事件
    pub fn session_events(&self) -> async_channel::Receiver<SessionEvent>;         // subscribe("session:event") 的类型化版本
    pub fn handle_capability(&self, name: &'static str, h: CapabilityHandler);
    pub fn state(&self) -> ConnectionState;
    pub fn state_changes(&self) -> async_channel::Receiver<ConnectionState>;
    pub fn has_channel(&self, channel: &str) -> bool;                // 基于 registeredChannels
    pub fn server_version(&self) -> Option<String>;
    pub async fn switch_workspace(&self, id: &str) -> Result<(), RpcError>; // 调 window:switchWorkspace 并更新重连用 id
    pub fn replace_endpoint(&self, ep: Endpoint);                  // sidecar 重启后调用，触发全新连接
    pub fn close(&self);
}

pub type CapabilityHandler = Arc<dyn Fn(Vec<Value>) -> BoxFuture<'static, Result<Value, WireError>> + Send + Sync>;

pub enum RpcError { Wire(WireError), Timeout, Disconnected, ChannelUnavailable(String), Decode(serde_json::Error) }
```

**类型化门面**：`agentkit_client::api` 对 02 页频道表中的每个频道提供一个强类型方法，分组为 `sessions()`、`workspaces()`、`connections()`、`settings()`、`files()`、`skills()`、`oauth()`、`drafts()`。例：

```rust
let r: SendAck = client.sessions().send_message(&session_id, &text, attachments, stored, opts).await?;
client.sessions().respond_to_permission(&session_id, &request_id, true, false).await?;
client.sessions().command(&session_id, SessionCommand::SetPermissionMode { mode: PermissionMode::AllowAll }).await?;
```

界面代码只允许调用 `api`，禁止直接传字符串频道名（clippy 自定义 lint 或代码评审把关）。长耗时频道的超时在门面内固定：`sendMessage` 300 秒、`storeAttachment` 120 秒、`searchContent` 15 秒、`export` / `import` 120 秒。

**实现要点**

- 请求表 `HashMap<id, oneshot::Sender>`；超时与断线都从表中移除并回错。
- 订阅表 `HashMap<channel, Vec<Sender>>`；发送失败（接收端已 drop）时自动清理。
- 能力请求在独立任务中执行，不阻塞读循环。
- 发送前检查序列化后大小 ≤ `maxMessageBytes`，超限直接返回 `Wire(TRANSFER_TOO_LARGE)`。
- token 使用 `secrecy::SecretString` 保存，`Debug` 不输出明文。
- 单测使用仓库内 `tests/support/mock_server.rs`（基于 async-tungstenite 的小型服务端）；契约测试使用真实 sidecar（见 05 页）。

## agentkit-store

职责：把服务端状态缓存为 GPUI Entity，并把事件流归约为可渲染的视图模型。分两层：

- `agentkit_store::core`：纯函数，不依赖 GPUI，100% 单测覆盖。
- `agentkit_store::entities`：GPUI Entity，只负责调用 core 并发通知。

### entities

| Entity | 数量 | 内容 | 更新来源 |
| --- | --- | --- | --- |
| `AppState` | 全局 1 个 | 连接状态、服务版本、已注册频道、模型连接列表、未读汇总、偏好 | 客户端状态、`LLM_Connection:changed`、`sessions:unreadSummaryChanged` |
| `WorkspaceStore` | 每窗口 1 个 | 当前工作区、工作区列表、工作区设置、Skills | `workspaces:get`、`skills:changed` |
| `SessionListStore` | 每窗口 1 个 | 会话摘要列表、当前筛选、搜索结果 | `sessions:get` + 摘要级事件（下述） |
| `SessionStore` | 每个打开的会话 1 个 | `SessionState`、分组后的 `Vec<Turn>`、待审批列表、草稿 | `sessions:getMessages` + `core::reducer` |

**事件路由**：每个窗口启动一个 `cx.spawn` 任务读取 `session_events()`。每次唤醒用 `try_recv` 一次取完已到事件（上限 256 条），按 `sessionId` 分发：对已打开会话调用归约器；对所有会话更新列表摘要。一批处理完每个 Entity 只 `cx.notify()` 一次，实现“同帧合并”。

**列表摘要级事件**：`user_message` / `text_delta` / `tool_start` → `isProcessing=true`；`complete` / `interrupted` / `error` → `isProcessing=false`；`permission_request` → 标记待审批（`respondToPermission` 或 `complete` 后清除）；`plan_submitted` → 标记待审计划；`title_generated` / `name_changed` / `session_flagged` 等 → 对应字段；`session_created` / `session_deleted` → 增删。

**流式快速路径**：`text_delta` 不重新分组回合，只向 UI 发 `SessionStoreEvent::StreamDelta { message_id, delta }`，UI 直接 `TextViewState::push_str`。其他改变消息列表的事件发 `TurnsChanged { from_turn }`，只重算并重绘受影响的末尾回合。

**乐观发送**：`SessionStore::send(text, attachments)` 先插入 `isPending` 用户消息（处理中发送时同时 `isQueued`）、置 `isProcessing=true`，再调用 `sendMessage`；调用失败则移除乐观消息、恢复输入并提示。

**待执行计划调度器**：在“会话打开”“收到 compaction\_complete”“会话变为空闲”三个时机调用。流程：会话忙则返回 → `getPendingPlanExecution` → 无记录或已派发则返回 → `markPendingPlanExecutionDispatched` → 发送批准消息 → `clearPendingPlanExecution`。同一会话同时只允许一个调度进行中。

## agentkit-ui

职责：可复用的 Agent 视图。组件只读 Entity、通过 `EventEmitter` 向外发事件，**不直接调用 RPC**（RPC 由 agentkit-app 的控制器调用），便于下游产品替换与测试。所有组件须支持亮 / 暗主题、键盘操作、AccessKit 角色。

**消息渲染规则**

- `ChatView` 的行 = 一个 `Turn`；`MessageScrollerState::append` / `splice` 与 `TurnsChanged` 对齐；跟随尾部时新内容自动滚动，用户上滚后出现“跳到最新”。
- 每条助手文本对应一个 `Entity<TextViewState>`，以 message id 为键缓存在 `ChatView`；`text_complete` 时用最终文本 `set_text` 一次校正。离开可视区超过 200 行的缓存可以释放。
- 工具结果默认折叠，只显示摘要行（工具名 + intent + 耗时 + 状态）；展开后按类型显示：`edit` / `write` 用 `Diff`，代码类结果用只读 `Editor`，其余用等宽文本；超过 2,000 行只显示前 2,000 行并提供“在编辑器中打开完整结果”。
- 嵌套子 Agent 工具按 `parentToolUseId` 缩进，缩进深度上限 4 层。
- 自定义工具卡：按工具名查 `ToolRendererRegistry`（由 `AgentApp::tool_renderer` 注册），未注册时用通用 `ToolCard`。

## agentkit-app

职责：应用骨架。把 sidecar、client、store、ui 串起来，并持有所有“控制器”（把 UI 事件翻译为 RPC 调用的代码）。

### 启动序列

1. 解析 `brand.toml`；初始化日志；单实例检查（已有实例则发送“聚焦”后退出）。
2. `gpui_kit::application().with_assets(Assets).run(|cx| { gpui_kit::init(cx); … })`。
3. 读取本地偏好，应用主题与语言。
4. `gpui_kit::open_window(…)` 打开主窗口，先显示启动骨架屏（首帧 ≤ 300 ms）。
5. 后台 `SidecarHandle::start` → `RpcClient::connect` → `server:getHealth` → 拉取工作区、连接、会话列表。
6. 无已认证连接 → 引导；否则进入工作台，打开上次的会话。

### 对外 API（框架扩展点）

```rust
    pub fn command(self, id: &str, label: &str, f: CommandFn) -> Self;
    pub fn settings_page(self, title: &str, f: SettingsPageFn) -> Self;
    pub fn capability(self, name: &'static str, h: CapabilityHandler) -> Self;

}
pub struct Brand { pub app_name: String, pub bundle_id: String, pub data_dir_name: String,
                   pub url_scheme: String, pub default_theme: String, pub icon: &'static [u8],
                   pub update_feed: Option<String> }
```

### 窗口与控制器

| 类型 | 数量 | 职责 |
| --- | --- | --- |
| `AppController` | 全局 | sidecar 与客户端生命周期、窗口列表、全局动作（新窗口、退出、设置）、通知与角标 |
| `WorkbenchWindow` | 每窗口 | 根视图；持有本窗口的 `RpcClient`（独立连接、独立 workspaceId）、`WorkspaceStore`、`SessionListStore`、已打开的 `SessionStore` |
| `SessionController` | 每个打开的会话 | 订阅 `ChatView` / `Composer` / `PermissionPrompt` / `PlanCard` 事件并调用对应 RPC；处理归约器 `Effect`；发送时走 01 页 U5 的附件流程；打开会话时发 `setActiveViewing` 并 `markRead` |
| `SettingsController` | 设置窗口 | 设置页读写；代理变更后调用 `SidecarHandle::restart` |
| `OnboardingController` | 引导时 | 移植上游 `apps/electron/src/renderer/hooks/useOnboarding.ts` 的状态机与 slug 规则（`resolveSlugForMethod`） |

**布局**：`TitleBar` + 左侧 `Sidebar`（可收起，240–420 px）+ 中间会话区 + 右侧面板（文件 / 计划 / 后台任务 / 扩展面板，默认收起，280–560 px）+ `StatusBar`。用 `Resizable` 实现宽度拖拽，宽度与收起状态写入本地偏好。尺寸细节见 04 页。

**动作与快捷键**：用 `gpui_kit::actions!` 在 `agentkit_app::actions` 集中声明，`keymap.rs` 绑定默认键位（见 04 页），用户覆盖写在 `keymap.json`。菜单用 `cx.set_menus`，菜单项绑定同一组 Action。

**国际化**：构建脚本把上游 `packages/shared/src/i18n/locales/en.json`、`zh-Hans.json`（扁平键，i18next `{{var}}` 插值）转换为 rust-i18n 格式（`%{var}`），按需只保留引用到的键。自有文案放在 `crates/agentkit-app/locales/`，键名用 `ak.` 前缀避免冲突。代码中只允许 `t!("key")`，CI 检查中英键集一致且无硬编码中文 / 英文句子。

**主题**：只使用 GPUI Kit 内置主题与语义 Token；默认 `brand.default_theme`，支持“跟随系统”。不调用后端 `theme:*` 频道（主题属于客户端偏好）。

**单实例**：启动时用 `interprocess` 尝试连接本地 socket（Unix `<data_dir>/app.sock`，Windows 命名管道 `\\.\pipe\<bundle_id>`）。连上即发送 `{"cmd":"focus"}` 或 `{"cmd":"open-url","url":…}` 后退出；连不上则自己监听。

## agentkit-capabilities

职责：所有和操作系统打交道的代码。每项能力一个模块，平台差异用 `#[cfg(target_os)]` 隔离。

| 模块 | 功能 | 实现要点 |
| --- | --- | --- |
| `client_caps` | 注册 02 页 5 个 `client:*` 处理器 | 处理器通过 `AsyncApp` 切到前台线程；对话框父窗口取最近聚焦窗口 |
| `oauth_chatgpt` | ChatGPT Plus 登录 | 先在 `127.0.0.1:1455` 启动 `tiny_http`（路径 `/auth/callback`）；端口被占用时提示并中止 → `chatgpt:startOAuth(slug)` → `cx.open_url(authUrl)` → 等回调（超时 5 分钟）→ 有 `error` 参数则 `cancelOAuth{state}`，否则 `completeOAuth{flowId, code, state}` → 回调页返回简单 HTML（“可以关闭此页”）→ 关闭服务。与上游 `apps/electron/src/preload/bootstrap.ts` 中 `startChatGptOAuth` 一致 |
| `oauth_claude` | Claude Pro/Max 登录 | `onboarding:startClaudeOAuth` → 打开 `authUrl` → 用户粘贴授权码 → `exchangeClaudeCode(code, slug)` → 成功后 `settings:setupLlmConnection{slug, credential: token, oauthIdentity}`；取消时 `clearClaudeOAuthState` |
| `notifications` | 系统通知 | 触发条件：窗口非前台且（`complete` 或 `permission_request` 或 `plan_submitted`）；点击后激活应用并定位工作区 + 会话；开关存本地偏好；macOS 首次使用时请求授权 |
| `badge` | 未读角标 | macOS `NSApp.dockTile.badgeLabel`；Windows 任务栏叠加图标；Linux Unity LauncherEntry（可选） |
| `power` | 防休眠 | 任一会话 processing 且开关打开 → `keepawake` 保持；全部空闲后释放 |
| `files` | 附件读取 | 拖拽、粘贴、选择的文件读为 `FileAttachment`：图片转 base64 并生成 ≤ 256 px PNG 缩略图；文本类读 `text`；其余只传路径与 base64；单文件 > 50 MB 拒绝 |
| `deeplink` | `<url_scheme>://` | 阶段 3；macOS Info.plist `CFBundleURLTypes`、Windows 注册表、Linux `.desktop`；参数与上游 `DeepLinkNavigation` 一致 |
| `updater` | 自动更新 | 阶段 3；Velopack；启动 60 秒后及每 6 小时检查；下载完成后提示“重启以更新” |

## 日志、诊断与本地配置文件

**目录**（以 macOS 为例，其余平台用 `directories` 的对应目录）

| 路径 | 内容 | 写入方 |
| --- | --- | --- |
| `~/.agentkit/` | 后端数据目录（工作区、会话 JSONL、凭据、Skills） | 只有后端 |
| `~/Library/Application Support/<bundle_id>/prefs.json` | 客户端偏好（主题、语言、窗口尺寸与位置、面板宽度、上次会话、通知开关、首次启动标记） | 客户端 |
| `~/Library/Application Support/<bundle_id>/keymap.json` | 用户快捷键覆盖 | 用户 / 客户端 |
| `~/Library/Logs/<bundle_id>/app.log` | GPUI 进程日志 | 客户端 |
| `~/Library/Logs/<bundle_id>/sidecar.log` | 后端 stdout / stderr | agentkit-sidecar |

`prefs.json` 带 `"version": 1`，写入时先写临时文件再原子替换；解析失败则备份为 `prefs.json.bak` 并用默认值。

**日志规范**：`tracing` 结构化日志；按天滚动，保留 7 天，单文件上限 20 MB。release 默认 `info`，环境变量 `AGENTKIT_LOG=debug` 可调。禁止写入日志的内容：RPC token、API Key、OAuth code / token、用户消息正文、工具入参与结果正文（只记长度与 id）。RPC 日志只记 `channel`、`id`、耗时、错误码。

**诊断包**（F-41）：帮助菜单“导出诊断信息”生成 zip：`app.log`、`sidecar.log`（最近 3 天）、`prefs.json`、版本信息、`system:versions`、连接列表（只含 slug 与类型、认证状态）。生成后在文件管理器中显示。

**关于页与开源署名**：“关于”窗口显示应用版本、后端版本（`serverVersion`）、mkagent 上游 tag、GPUI Kit 版本，以及 Apache-2.0 与 NOTICE 署名。
