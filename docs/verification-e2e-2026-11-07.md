## 已实现

可选 e2e 构建启动正式 Workbench。驱动操作实际输入状态、Composer、连接表单和正常审批/取消意图；业务经正式 controller、类型化 API、认证 WebSocket、自带 Bun 与 Pi，不预建连接或注入会话事件。正常构建不包含驱动和故障接口。

本地 HTTP 模型只返回流式文本和 Read/Write 请求。后端真正执行工具；模型核验 Read 结果，runner 核验允许/始终允许的文件和被拒绝文件不存在。先验证失败连接不能保存，再测试成功、保存、默认连接、聚焦空输入框。用户乐观消息仅一份，真实 ACK/事件归一，Markdown 缓存包含最终正文。

v0.2.6 的 compact transcript 不保存临时工具消息。U2 快照断言比较用户/助手规范身份、角色、正文，ID 使用真实 user_message 的映射；另以应用重启后7条用户消息各一次、5种确定性回复验证磁盘恢复。不会声称工具历史已持久化。

崩溃注入仅使用监督器已拥有的进程句柄杀死 leader；正常监督器回收/重启，验证新 token、断连阶段、全量恢复、历史保全、列表无重复、未发送草稿、本次崩溃之后的新中断提示，以及继续对话。不是主动重启冒充崩溃。

P-04 解决连接探测在用户主目录建 sessions 的错误，改用独立临时目录并清理。P-05 加入私有活动回合标记，按会话串行化显式保存边界；独占创建避免截断，写失败传播且保留证据，发送预留失败恢复 idle，初始化提示以稳定身份去重。没有协议字段或固定 tag 变更。Linux subreaper 区分已死后代与活着的泄漏；前者只回收，后者仍使门禁失败。
