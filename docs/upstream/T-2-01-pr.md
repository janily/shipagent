## Proposed title

fix(server): persist headless proxy and keep-awake settings

## Proposed body

The standalone server currently exposes the read operations for network proxy and keep-awake preferences, while their write handlers are registered only by Electron. This adds standalone-only handlers: proxy writes return `{ restartRequired: true }`, and keep-awake writes persist the preference without invoking OS power APIs. Electron keeps its existing GUI handlers.

Before standalone bootstrap starts networking, saved settings configure the protocol-aware undici dispatcher and Bun fetch routing. HTTP/HTTPS proxies, HTTPS fallback and NO_PROXY retain the existing Electron matcher's semantics. Bun's environment-backed proxy caching makes this startup-only: saving settings does not change the running process. Empty/disabled configuration clears inherited proxy routing so a restart cannot silently re-enable an ambient proxy.

Proxy parameters and credential encodings are validated before persistence. Missing, corrupt or unwritable configuration returns a fixed error instead of a false acknowledgement; constructor/parser errors cannot disclose proxy credentials. The interceptor preserves an explicit per-request proxy option, including the direct request path used by headless routing.

Tests use local HTTP origins and two counting proxies, with fresh processes per configuration. They verify actual Bun/undici HTTP requests, HTTPS CONNECT proxy selection/refusal, fallback, NO_PROXY matching/nonmatching ports, disabled/unconfigured routing under existing ambient proxy variables, persistence acknowledgements, malformed parameters and damaged configuration. HTTPS fixtures deliberately refuse CONNECT: they test proxy selection, not external TLS or enterprise CA deployment.

Validation:

```sh
CONFIG_DIR=$(mktemp -d) bun test ./packages/server-core/src/services/headless-proxy.test.ts ./packages/server-core/src/services/headless-proxy-utils.test.ts ./packages/server-core/src/handlers/rpc/headless-desktop.test.ts
bun run validate:ci
```

The consumer additionally verifies the bundled standalone server through authenticated WebSocket RPC: save settings, retain old live routing, restart with a new token, read settings back, observe the selected proxy, and persist/restore keep-awake. Actual OS sleep inhibition remains owned by the desktop client.
